# SUPABASE (YC S20) — Launch Week

**Steal: 4 · Fit: 3 · Included to be explicitly rejected for now.**

---

## The play

Supabase runs "Launch Week": a scheduled week where a feature ships every day, announced on a rhythm,
with the community watching live. It manufactures recurring attention on a predictable cadence instead
of hoping for one viral moment, and it turns shipping — which happens anyway — into an event.

## Why it scores 4

The mechanism is genuinely good and the **cadence** idea transfers. The format does not.

Launch Week works when you have (a) an audience already watching, (b) multiple shippable features in
flight, and (c) a product people use daily. We have none of the three. Running a Launch Week into an
empty room is a cost with no return, and worse, it burns the format for when we could use it.

## The part that does transfer

**Predictable publishing beats sporadic announcements.** Backblaze's quarterly Drive Stats is the same
insight with better fit for us: a cadence built on something that accumulates rather than on features
that have to be invented to fill the slots.

So the recommendation is: **take the cadence, leave the format.** Ours is *"the compatibility table is
updated whenever a machine is touched, and summarised on a fixed interval"* — a rhythm we can sustain
with no marketing team and no feature pipeline, and one that gets more valuable rather than more
expensive over time.

Revisit the actual format when there is an audience to run it for. That is a Gate 6+ question.
